# Synthora Antigravity Master Bible (Version 1.0)

## Purpose

This document provides the permanent context that every Antigravity page
generation prompt must inherit.

------------------------------------------------------------------------

# 1. Product Context

Synthora is a specialized B2B procurement platform for the chemical and
pharmaceutical industry.

It is NOT: - A generic SaaS dashboard - An e-commerce store - A consumer
marketplace - IndiaMART with a new UI

It IS: - Product-centric - Procurement-first - Enterprise-grade -
Search-driven - Trust-focused

------------------------------------------------------------------------

# 2. Core Product Philosophy

Every screen must help users accomplish one of two goals:

1.  Help buyers discover trusted suppliers faster.
2.  Help suppliers receive high-quality business inquiries.

Avoid features that do not support these goals.

------------------------------------------------------------------------

# 3. Design Philosophy

Visual keywords: - Professional - Trustworthy - Premium - Modern
Enterprise - Scientific - Clean - Balanced

Avoid: - Glassmorphism - Neon gradients - Floating blobs - Gaming
aesthetics - Overly colorful dashboards

------------------------------------------------------------------------

# 4. Brand System

Primary: #103A5E Secondary: #14B8A6 Accent: #3B82F6 Background: #F8FAFC

Typography: Inter

Theme: Light

------------------------------------------------------------------------

# 5. Layout Rules

-   Container-based layout
-   Balanced whitespace
-   Responsive grid
-   Sticky navigation
-   Consistent spacing
-   Search-first experience

------------------------------------------------------------------------

# 6. Navigation Philosophy

Marketplace remains consistent.

Authentication unlocks functionality.

Supplier receives a dedicated Supplier Workspace.

Admin receives an Operations Workspace.

Never create separate buyer dashboards.

------------------------------------------------------------------------

# 7. UX Rules

-   Minimize clicks.
-   Progressive authentication.
-   Product before supplier.
-   Supplier comparison tables.
-   Clear calls-to-action.
-   Consistent page hierarchy.

------------------------------------------------------------------------

# 8. Product Page Standard

Sections: 1. Summary 2. Technical Information 3. Applications 4.
Specifications 5. Documents 6. Supplier Comparison 7. Related Products

Master product owned by Synthora.

Suppliers attach listings.

------------------------------------------------------------------------

# 9. Search Standard

Search supports: - Product Name - CAS - Synonyms - Supplier - Category -
City - State

Ranking: Sponsored Exact Match CAS Match Product Match Verified Supplier
Related Products

------------------------------------------------------------------------

# 10. Component Standards

Buttons: Filled + Outline

Cards: Subtle border

Tables: Enterprise style

Animations: 150--250ms only

Icons: Lucide

Forms: Simple, guided, validation-first

------------------------------------------------------------------------

# 11. Responsive Rules

Desktop: Full experience

Tablet: Collapsible navigation

Mobile: Optimized search, cards replacing dense tables where needed.

------------------------------------------------------------------------

# 12. Accessibility

-   High contrast
-   Keyboard navigation
-   Semantic headings
-   Accessible forms
-   Clear focus states

------------------------------------------------------------------------

# 13. Page Prompt Template

Every Antigravity page prompt should include:

-   Page objective
-   Target user
-   Business purpose
-   Required sections
-   Component requirements
-   Interaction requirements
-   Responsive behaviour
-   Accessibility requirements
-   Success criteria

Do not generate decorative UI without functional value.

------------------------------------------------------------------------

# 14. Success Criteria

Every generated page should: - Feel like enterprise procurement
software. - Match the Synthora design system. - Reuse established
components. - Prioritize readability. - Support procurement workflows. -
Avoid unnecessary dashboards and analytics.
